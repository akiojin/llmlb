# 組織とアカウント別の利用管理

Issue #947 の組織は、共有する推論URLの管理・閲覧境界です。アカウントの所属は0または1組織で、組織内の役割は admin または member です。既存のシステム管理者権限は独立して扱います。組織内 admin に全体設定の変更権限はありません。

## 閲覧と管理

| 主体 | 組織・所属の変更 | 利用情報・アカウント・キー | リクエスト詳細・出力 |
| --- | --- | --- | --- |
| システム管理者 | 全組織 | 全体と未帰属 | 全体 |
| 組織 admin | 不可 | 現在の所属組織 | 現在の所属組織 |
| 組織 member | 不可 | 現在の所属組織内の本人 | 現在の所属組織内の本人 |
| 未所属・無効アカウント | 不可 | 不可 | 不可 |
| 新しい帰属APIキー | 不可 | 不可 | 不可 |

閲覧にはJWTでログインします。サーバーは毎要求でDBの現在の所属と権限を確認します。JWTの古いrole、クライアントが送る組織ID、キー発行者のIDで閲覧範囲を拡大できません。

旧viewerが全体統計を読めた挙動は、所属組織内の本人の範囲へ変わります。組織adminは自組織の利用だけを確認できます。詳細ID・絞込み・全件件数・合計・ページ数・CSVも同じ範囲で処理します。

既存の未帰属UsersManage管理キーによるusers・登録申請管理と、MetricsRead管理キーによるcloud metricsは互換例外です。これらのキーを新しい組織の閲覧資格として使うことはできません。

## 移行

1. システム管理者が組織を作成します。空名・有効組織と重複する名前は使えません。
2. 対象アカウントに所属組織と組織内の役割を明示的に設定します。未所属アカウントには所属設定を案内します。
3. 利用アカウントと同じ有効組織へ帰属する新しいAPIキーを発行します。発行者は監査情報として残し、利用アカウントと区別します。
4. 利用先を新しいキーへ切り替えます。導入前の未帰属キーの失効は別の明示操作です。

導入前のキーや履歴は、created_byだけで利用者や組織を推測しません。証明できない帰属はシステム管理者だけが確認できる「未帰属」として扱います。旧キーを無断で全失効したり、旧履歴を新しい所属へ付け替えたりしません。過去に削除された履歴は復元できません。

アカウントが移籍・所属解除した後は、それまでの帰属キーを永続失効させます。元の組織に戻っても復活しません。有効な所属を設定し、新しいキーを発行してください。移籍前に受理した要求は、stream終了が移籍後になっても元の組織に残ります。削除・改名・アーカイブで過去の帰属や利用合計を再配賦しません。在籍アカウントが残る組織はアーカイブできません。

## 集計の意味

受理した推論要求のUUIDとUTC受付日時を固定し、内部の転送再試行は同じ要求として扱います。認証拒否・入力拒否・管理API・health・pollingは推論利用の件数に含めません。成功・失敗・中断を含む受理済み要求を計上します。

期間はUTCです。画面で選ぶfrom/toは両端の日を含み、サーバー内部では翌日の開始を終端とする半開区間で処理します。既定は当月です。ページの行数とは別に、認可範囲と期間全体の合計を返します。

有効なproviderのトークン数を優先し、推定値・部分欠測・未報告を区別します。未報告を実測0に変換しません。観測開始時期、欠測と推定の件数を確認してください。raw履歴の保持期間と独立した日次集計を使うため、7日のraw cleanup後も導入後の期間合計を保持します。

確定済みの成功・失敗件数も日次集計へ保存します。受付中や再起動時の回収など、成否を証明できない要求は失敗へ推測せず、成功率の分母から除きます。HTTP 200のstreamでも構造化された上流エラーを受け取った場合は失敗として記録します。

月間quotaの受付制御は後続のIssue #949です。本変更で上限制御が有効になったとは表示しません。

## 検証するサーバー境界

| 面 | 対象モジュール | 必要な境界 |
| --- | --- | --- |
| JWT・APIキー | auth/middleware、auth/scope | DB現在主体、利用帰属と発行者の分離、旧キーの移籍拒否 |
| 組織・所属 | api/organizations、api/users、db/organizations | globalのみ変更、SQLで所属の一意性と有効性を保証 |
| 全推論入口 | OpenAI、Responses、Anthropic、画像・音声、LB/Endpoint Playground、Load Test | 入力検証後・転送前の受付保存、EOF/error/Dropで一度だけ精算 |
| 履歴・永続集計 | db/request_history、db/usage | 同一transaction、UUID重複排除、raw削除後もonceを保持 |
| overview・activity | api/dashboard、dashboard/overview | 全体メモリ値や全体cacheを非globalへ返さない |
| endpoint・model統計 | dashboard/endpoint_stats、api/endpoints | 共有inventory内の利用counterにも閲覧範囲を適用 |
| token統計 | dashboard/token_stats | UTC受付bucketと永続日次集計を使用 |
| 履歴・検索・詳細・export | dashboard/request_history、db/request_history | SQL取得・全件COUNT・pagination・CSVの前に認可範囲を適用 |
| client/IP分析 | dashboard/clients、db/request_history/clients | ranking・timeline・件数・key一覧を同じ範囲に制約 |
| アカウント・キー一覧 | api/users、api/api_keys | 発行者基準の旧一覧と利用者の閲覧資格を混同しない |
| WebSocket | api/dashboard_ws | DB現在値で既存global専用境界を検査 |
| ブラウザ | useAuth、API client、各ViewModel | session/所属変更時のquery取消・cache破棄、旧応答と旧plaintextの再注入を防止 |

この台帳は検証対象です。現在世代の完了状態はIssue #947のT101〜T109と実行証跡で管理します。
